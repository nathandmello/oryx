# Reference context

Keep reusable information under its entity. Start company context in `company/overview.md`, product context in `products/<product>/overview.md`, and your profile in `pm/context.md`. Keep working relationships in `stakeholders/overview.md`.

A product and its area have separate briefs. Use the team’s term in `products/<product>/<group>/<area>/overview.md`, such as `plugins/salesforce/`. Find existing homes and earlier inline entries through the [product walkthrough](../../../playbook/product-context.md).
File initiative guidance in `products/<product>/initiatives/<initiative>/overview.md`. Save briefs, experiments, and planning comparisons in the [workspace](../workspace/README.md).

Add only the sections and files that current evidence supports. Use [the filing rules](../../../playbook/filing.md) before naming a new topic folder. Use [the context rules](../../../playbook/context.md) for source coverage, decisions, and unknowns.
