# Strategy review brief

Use this review after the strategy command reports `ready-for-pm-review`. The PM uses the brief to decide which problem to pursue.

## Trace the argument

- Why and Who. Show which business need this customer problem affects. State an unresolved goal as a gap.
- Who and What. Compare the selected problem and alternatives. Show why the evidence favours the first problem for the goal.
- What and How. Explain how the proposed approach changes customer behaviour and which measure can show that effect.
- Evidence. Follow cited context entries back to the original excerpts. Check the strongest supporting and contrary evidence. Name limits that affect the choice.
- Context. Carry parent commitments and approved exceptions into the argument. Preserve the actor, exclusions, conditions, scope, and dates from the source.
- Risks. Show the four owners and each open question or sourced assessment. Keep blockers separate.
- Value validation. Check demand for the chosen users, observed impact on their process, and the test that supports requirements and priority.

An agreed plan leaves value open until the test result supports it. Apply the [original value criteria](../../../../playbook/sources/product-strategy-mindset.md#validating-value-who--what--how).

Keep the brief at the current stage if the argument depends on a missing fact. In thought-partner mode, ask for the smallest input that can resolve it.

## Present the decision

Use these headings for a requested review. Link the authoritative strategy record.

- Proposed choice
- Why this customer problem comes first
- Evidence and strongest contrary evidence
- Expected effect, measure, and next value test
- Open risks, blockers, and the decision for the PM

Record an accepted choice only with a documented PM decision. Preserve its scope, date, source, and stated rationale.
